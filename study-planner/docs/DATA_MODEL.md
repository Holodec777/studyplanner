# Модель данных

## Сущности

### User — пользователь

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | integer | первичный ключ |
| `username` | string, 32 | уникальный, индекс |
| `password_hash` | string, 256 | PBKDF2-хеш, исходный пароль не сохраняется |
| `role` | string, 16 | `student` или `admin` |
| `is_active` | boolean | отключенный пользователь не может войти |
| `created_at` | timestamp | время создания |

### Assignment — учебная задача

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | integer | первичный ключ |
| `title` | string, 120 | от 3 до 120 символов |
| `description` | string, 1000 | необязательное описание |
| `subject` | string, 80 | от 2 до 80 символов |
| `due_date` | date | обязательный срок |
| `priority` | string | `low`, `medium` или `high` |
| `status` | string | `planned`, `in_progress` или `done` |
| `owner_id` | integer | внешний ключ на `users.id`, удаление пользователя удаляет его задачи |
| `created_at`, `updated_at` | timestamp | время создания и последнего изменения |

## Связи

Один пользователь может иметь много задач (`users.id → assignments.owner_id`). Для владельца и срока есть составной индекс; допустимые роли, приоритеты и статусы дополнительно ограничены в базе.

## Хранение

Схема управляется миграциями Alembic. Приложение использует PostgreSQL в Docker Compose; тесты создают отдельную SQLite-базу во временной папке для каждого теста.
