# User story и правила доступа

## Роли

| Роль | Что может делать |
|---|---|
| Ученик | Создавать, просматривать, изменять статус и удалять только свои задачи. |
| Администратор | Просматривать задачи всех учеников, назначать задачу ученику и изменять или удалять любую задачу. |

Вход выполняется по логину и паролю. Пароли хранятся в виде PBKDF2-хеша, API выдает Bearer-токен со сроком действия 12 часов.

## User story

### Ученик планирует учебу

Как ученик, я хочу добавлять задания с предметом, сроком и приоритетом, чтобы видеть ближайшую нагрузку и вовремя сдавать работу.

**Критерии приемки**

- Задача сохраняется с названием, предметом, сроком и статусом.
- Пустые названия и некорректные значения отклоняются API.
- Ученик видит только задачи своего аккаунта.
- Статус задачи можно изменить на «Запланировано», «В работе» или «Готово».
- Сводка показывает количество задач, ближайшие сроки, просроченные и выполненные задачи.

### Администратор помогает ученикам

Как администратор, я хочу видеть общий список задач и назначать задачу ученику, чтобы контролировать учебный план.

**Критерии приемки**

- Администратор видит список активных аккаунтов и задачи всех учеников.
- Администратор может указать владельца при создании задачи.
- Ученик не может читать или изменять чужую задачу и не может назначить задачу другому пользователю.

## Основные сценарии

1. Ученик входит в демо-аккаунт, проверяет задачи и добавляет новую.
2. Ученик меняет статус задачи, находит ее поиском или фильтром, затем может удалить.
3. Администратор входит в отдельный аккаунт, просматривает общий план и назначает задачу ученику.

Демо-аккаунты для локального запуска указаны в README.
